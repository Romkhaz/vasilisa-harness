# Сборка Агента Василисы

Приложение состоит из двух частей: серверная часть на Rust (бинарь `goose`) и десктоп-обо­лочка
на Electron. Сборка всегда идёт в одном порядке: сначала бинарь, потом оболочка, которая
кладёт бинарь внутрь пакета.

**Кросс-сборки нет.** Пакет под macOS собирается только на macOS, под Linux — только на
Linux, под Windows — только на Windows. Причина не в Rust, а в Electron Forge: он подписывает
бандл, собирает `.app` и `.deb` и вызывает системные утилиты целевой платформы.

## Что нужно на любой платформе

| Инструмент | Версия | Проверка |
|---|---|---|
| Rust | как в `rust-toolchain.toml` | `cargo --version` |
| Node.js | 24.10 или новее | `node -v` |
| pnpm | 10.30 или новее | `pnpm -v` |

Если pnpm не установлен, его ставит corepack, входящий в Node:

```bash
corepack enable pnpm
```

## macOS

Собирается на вашем маке. В релиз идёт только Apple Silicon — Intel-задание из
`release.yml` убрано. Собрать пакет под Intel по-прежнему можно вручную, порядок ниже.

1. Соберите серверную часть и положите её туда, откуда её заберёт оболочка:

```bash
cargo build --release -p goose-cli --bin goose
```

```bash
mkdir -p ui/desktop/src/bin && cp target/release/goose ui/desktop/src/bin/goose && chmod +x ui/desktop/src/bin/goose
```

2. Соберите приложение:

```bash
cd ui/desktop && pnpm install --frozen-lockfile && pnpm run make
```

Результат:

- `ui/desktop/out/Vasilisa-darwin-arm64/Vasilisa.app` — само приложение;
- `ui/desktop/out/make/Vasilisa.dmg` — установщик: окно с приложением и ярлыком
  «Программы», куда его перетаскивают;
- `ui/desktop/out/make/zip/darwin/arm64/Vasilisa-darwin-arm64-1.0.0.zip` — архив,
  его использует автообновление.

Для ручной Intel-сборки на Apple Silicon нужен ещё и Rust-бинарь под x86_64, иначе
внутрь пакета попадёт arm64-бинарь. Учтите: шаг компиляции переводов на самом Intel-маке
не отработает — `@formatjs/cli` не публикует нативный бинарь под `darwin-x64`.

```bash
rustup target add x86_64-apple-darwin
```

```bash
cargo build --release --target x86_64-apple-darwin -p goose-cli --bin goose && cp target/x86_64-apple-darwin/release/goose ui/desktop/src/bin/goose
```

```bash
cd ui/desktop && ELECTRON_ARCH=x64 pnpm run make --arch=x64
```

Образ `.dmg` собирает хук `postMake` в `ui/desktop/forge.config.ts` — обычным `hdiutil`
из состава macOS. Мейкер `@electron-forge/maker-dmg` для этого не годится: он тянет
`appdmg` с нативными `fs-xattr` и `macos-alias`, а `fs-xattr` (в его манифесте
`os: ['!win32']`) при чистой установке pnpm не ставит вовсе, и сборка на раннере падает
на `Cannot find module 'fs-xattr'`.

Сборка не подписана сертификатом Apple, но бандл подписывается ad-hoc: это делает хук
`postPackage` в `ui/desktop/forge.config.ts`. Без него packager и `FusesPlugin` правят
`Info.plist` и бинарь уже после подписи, унаследованной от Electron, подпись перестаёт
сходиться, и скачанное приложение macOS объявляет повреждённым. Если заданы `APPLE_ID`,
`APPLE_ID_PASSWORD` и `APPLE_TEAM_ID`, хук не вмешивается — `forge.config.ts` включает
настоящую подпись и нотаризацию.

При первом запуске macOS всё равно предупредит о неизвестном разработчике — порядок
действий в [руководстве пользователя](РУКОВОДСТВО.md).

## Linux

Собирается на вашей виртуалке. Проверялось на Ubuntu 22.04 и новее.

1. Поставьте системные зависимости — без них мейкер `.deb` не отработает:

```bash
sudo apt-get update && sudo apt-get install -y build-essential pkg-config libssl-dev dpkg fakeroot
```

2. Соберите серверную часть:

```bash
cargo build --release -p goose-cli --bin goose
```

```bash
mkdir -p ui/desktop/src/bin && cp target/release/goose ui/desktop/src/bin/goose && chmod +x ui/desktop/src/bin/goose
```

3. Соберите пакеты:

```bash
cd ui/desktop && pnpm install --frozen-lockfile && pnpm run make
```

Результат:

- `ui/desktop/out/make/deb/x64/vasilisa_1.0.2_amd64.deb`

Пакеты `.rpm` и `.flatpak` больше не собираются: целевой дистрибутив — Ubuntu, а каждый
лишний мейкер добавлял минуты к релизу.

## Windows

1. Соберите серверную часть:

```bash
cargo build --release -p goose-cli --bin goose
```

```bash
mkdir -p ui/desktop/src/bin && cp target/release/goose.exe ui/desktop/src/bin/goose.exe
```

2. Соберите приложение:

```bash
cd ui/desktop && pnpm install --frozen-lockfile && pnpm run make
```

Результат:

- `ui/desktop/out/make/squirrel.windows/x64/Vasilisa-setup.exe` — установщик;
- `ui/desktop/out/make/zip/win32/x64/Vasilisa-win32-x64-1.0.0.zip` — портативный архив.

## Сборка в GitHub Actions (основной путь)

Собирать руками не обязательно: по метке версии `v1.*` конвейер сам соберёт все
платформы и создаст релиз с готовыми файлами.

```bash
git tag v1.0.1 && git push origin v1.0.1
```

Дальше `release.yml` собирает три приложения — macOS (Apple Silicon), Linux и Windows —
и складывает их в релиз по тегу и в релиз `stable`: `Vasilisa.dmg` и `Vasilisa.zip`,
`Vasilisa-setup.exe` и портативный архив, `.deb`. Сборка CLI из релизного конвейера
пока убрана (`package_cli: false`, задание `build-cli-linux` не вызывается) — собрать
её можно через `workflow_dispatch`. macOS подписывается сертификатом Developer ID и
заверяется у Apple; секреты лежат в окружении `release`, доступ к ним закрыт правилами
защиты окружения. Сертификата Windows у проекта нет, эта сборка не подписана.

Отдельную платформу можно собрать без метки версии — через `workflow_dispatch`:

```bash
gh workflow run bundle-macos.yml -f target=aarch64-apple-darwin -f package_desktop=true -f signing=false
```

```bash
gh workflow run bundle-desktop-linux.yml
```

```bash
gh workflow run bundle-windows.yml -f package_desktop=true -f signing=false
```

Результат окажется в артефактах запуска (`gh run download`), а не в релизе.

### Сколько это стоит

Репозиторий приватный, поэтому минуты раннеров тарифицируются, причём с разной ценой:
Linux — ×1, Windows — ×2, macOS — ×10. Полный выпуск по метке версии задействует все
платформы, и дороже всего обходятся два macOS-задания. Если выпуски частые, есть смысл
собирать macOS на своём маке по инструкции выше, а CI оставить для Linux и Windows.

## Ручная сборка и выкладка в релиз

Если собираете локально, артефакты в репозиторий класть нельзя — они весят сотни
мегабайт, только в релиз:

```bash
gh release create v1.0.0 --title "Агент Василиса 1.0.0" --notes "Первая сборка" --draft
```

```bash
gh release upload v1.0.0 ui/desktop/out/make/squirrel.windows/x64/Vasilisa-setup.exe
```

С мака и с виртуалки — то же самое, `gh release upload v1.0.0 <путь к файлу>`; релиз общий,
файлы просто добавляются к нему. Когда все три платформы загружены, снимите черновик:

```bash
gh release edit v1.0.0 --draft=false
```
